## Step by step

### ① Landing from ManyChat — `/book`
- ManyChat asks its own questions in Instagram DMs, then sends the website link.
- The link goes **straight to the booking card**, not the home page. Tracking params
  (`source`, `campaign`, `mc` = ManyChat subscriber id) are kept on the lead.
- One form: **name, email, mobile number** (country code defaults to +91) → "Email me a code".
- We email a **6-digit code** (Resend). Entering it confirms the email and logs the person in.
  Code: generated by us, stored only as a hash, expires in 10 min, 5 tries, rate-limited.
- **The verified email is the account.** The phone is where the sales team calls (not verified).
- "Log in" (navbar) asks for the **email only**. If that email has no account yet, we then ask
  name + mobile before the calendar.
- Logged-in people skip this step. Someone with an upcoming call is sent to `/account`.

### ② Pick a time — `/book` (same card)
- Month calendar like Google Calendar (free days marked) + that day's times, plus a
  **"type a day and time"** box ("tomorrow 6:30 pm", "sat 11am") that picks or suggests the closest slot.
- One button: "Book Tue 28 Oct · 6:30 pm". Booking stays logged in (30-day cookie).
- No prices, no plans anywhere in this part of the site. The price is decided on the call.

### ③ Booked → `/account`
- After booking, go to `/account`: "You're booked — our team will call you on +91 ••••• 43210 at
  6:30 pm, Tue 28 Oct." Reschedule (button) / "Can't make it? Cancel" (small link) / Add to calendar.
- Email (Resend): booking confirmation, reminders (24 h + 1 h), quote ready, payment receipt.
- Navbar shows a **bell** with an unread count. "Book a call" hides while a call is booked.

### ④ Sales call — offline
- The sales team calls the customer's verified number at the booked time and negotiates.
- After the call they record the outcome in admin (completed / no-show).

### ⑤ Quote — admin
- Admin opens the booking or the lead and fills **one small form**:
  - Plan name (e.g. "12-week coaching")
  - Amount in ₹ (whatever was agreed on the call)
  - Plan length (e.g. 1 / 3 / 6 / 12 months, or a number of days)
  - Optional note
- "Send quote" → it goes to **that customer only**. It must be quick: the most common path is
  Bookings → today's call → Send quote.

### ⑥ Customer sees the quote and pays — `/account`
- The quote appears as a **notification** (bell + inbox) and as a banner on `/account`:
  "Your plan quote is ready · 12-week coaching · ₹12,000 → View & pay". Email too, if given.
- Pay with **Razorpay** (built; needs live keys). Stripe is undecided. The amount always comes
  from the server, never from the browser.
- After payment: "Payment received" notification, quote marked PAID, the plan becomes active.

### ⑦ Active plan — admin `/admin/clients`
- Every paying customer is listed with: **name, client ID, phone, plan, amount paid, paid on,
  valid from, valid until, status** (Active / Expiring soon / Expired).
- Valid from = payment date (default), valid until = from + plan length. **Admin can edit both
  dates** (late start, extension, free extra week) and add notes.
- Renewals = send a new quote; paying it adds a new plan period after the current one.
- The customer's `/account` shows "Your plan: 12-week coaching · active until 20 Jan 2027".

## Rules that keep the flow simple
1. One path for everybody: name + email + phone → email code → time. Never a sign-up/log-in choice
   on the booking link ("Log in" in the navbar is the only email-only entry).
2. Required before booking: name, verified email, phone. Nothing else.
3. The verified email identifies the account; never key accounts on the unverified phone.
4. Prices and plans are never public. They only exist as quotes to one customer.
5. Every customer-facing update is an in-app notification first; email is a bonus copy.
6. The admin panel is built for a busy sales person: fewest clicks from "call done" to "quote sent".

## Data (Prisma)
- `Lead` = the customer account (unique verified **email**, phone for calls, name, `clientCode` like RAHUL-4821).
- `Booking` = the sales call. `Quote` = plan + ₹ (+ plan length) sent to one lead. `Payment` = a Razorpay attempt.
- `Membership` = a paid plan period (lead, quote, plan, ₹, validFrom, validUntil, notes) — powers `/admin/clients`.
- `InboxItem` = in-app notification. `Notification` = email outbox (Resend) with retries.

## Before going live (checked 2026-10-23 audit)
- Resend: verify the sending domain; set `EMAIL_FROM` on it. Until then codes only reach the Resend owner.
- Vercel env: paste everything from `mithlesh/.env` (not in git; it holds the production values); set the real `APP_URL`. The site refuses to
  start with a placeholder `APP_URL`, a missing `RESEND_API_KEY` or an `@example.com` sender.
- Vercel runs `vercel-build` = `prisma generate && prisma migrate deploy && next build`, so database
  changes apply on deploy.
- External scheduler (e.g. cron-job.org) every 5 min → `GET /api/cron/notifications` with
  `Authorization: Bearer <CRON_SECRET>` (Vercel Hobby crons are daily only).
- Razorpay (when payments resume): turn ON auto-capture in the Razorpay dashboard. Extra or late
  payments are flagged "Refund needed" on the admin quote.
- Heavy traffic: Aiven's PgBouncer pool URL for `DATABASE_URL`; app uses 3 connections per instance
  (`DATABASE_POOL_MAX`).
